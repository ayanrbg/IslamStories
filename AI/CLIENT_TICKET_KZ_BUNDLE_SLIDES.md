# [Клиент/Unity] Казахские слайды не привязываются: обновить бандл `golden_egg`

**Тип:** Bug · **Приоритет:** High · **Компонент:** Unity-клиент (iOS + Android), `StreamingAssets/BundledTales/`
**Связано:** `CLIENT_TICKET_TALE_TEXT_REFRESH.md` (причина 1), `API.md §5`, `UNITY_INTEGRATION.md §gendered`,
коммиты сервера `99db33c`, `b4a71b4`

**Симптом:** во встроенной (bundled) сказке `golden_egg` на казахском слайды не привязываются
и не показываются. На русском и узбекском та же сказка работает.

**Причина найдена и на сервере уже исправлена.** От вас нужно одно действие — обновить текст
в бандле и выпустить сборку. Ниже подробности, потому что там же лежит вопрос, который стоит
закрыть, чтобы это не повторилось.

---

## 1. Что произошло

8 августа мы заменили все казахские тексты новым переводом (`99db33c`). Старый машинный перевод
оборачивал в `{m:X|f:X}` даже те страницы, где мужской и женский варианты были посимвольно
одинаковы; новый перевод такие пустышки убрал — 249 страниц по девяти сказкам.

Для текста это ничего не меняло, но структура казахских файлов впервые разошлась с русской
и узбекской. До правки все три языка помечали ровно одни и те же страницы, после — нет:

| | гендерные страницы в `golden_egg` |
|---|---|
| ru | 22: `0,1,2,3,6,7,9,11,19,22,23,24,25,26,32,33,37,40,42,43,45,46` |
| uz | те же 22 |
| kz **до** правки | те же 22 |
| kz **после** правки | 4: `0, 24, 25, 33` |

По остальным сказкам так же: `space_race` kz — с 22 до 0, `baursak` — с 20 до 1,
`magic_bird` — с 69 до 10.

Ломается ровно казахский и ровно на bundled-сказке — это и есть ваш симптом.

## 2. Что мы сделали на сервере

Коммит `b4a71b4`, уже в проде:

- вернули обёртки `{m:X|f:X}` ровно на тех страницах, которые обёрнуты в ru/uz (249 страниц,
  все девять сказок). Обёртка — на всю страницу целиком, ровно как в ru/uz;
- 37 страниц, где переводчик дал **настоящее** гендерное различие, не тронули — все они и так
  попадали в набор ru, лишних маркеров за пределами старого набора не было;
- залили в прод-БД, `contentVersion` казахских версий стал 3–4 в зависимости от сказки.

Наборы гендерных страниц у kz снова совпадают с ru/uz по всем сказкам. Проверить можно так:

```
GET /api/tales/golden_egg?lang=kz
→ страницы с {m:  →  0,1,2,3,6,7,9,11,19,22,23,24,25,26,32,33,37,40,42,43,45,46
```

Отрендеренный текст при этом не изменился ни на символ: обёртки прозрачны, после подстановки
имени и пола на выходе то же, что и до правки, для обоих полов. Перегенерировать озвучку
не нужно.

## 3. Что нужно от вас

`golden_egg` — единственная сказка с `bundled: true`. Её текст и иллюстрации лежат в
`StreamingAssets/BundledTales/` внутри сборки, сервер до них не дотягивается: наши правки
до пользователя не доходят в принципе, пока не выйдет новый билд.

**Забрать свежий файл и положить в бандл:**

```
data/tales/kz/golden_egg_kz.json   (ветка main, коммит b4a71b4)
```

Или из API — содержимое идентично:

```
GET /api/tales/golden_egg?lang=kz     → поле pages
```

Заодно проверьте узбекский и русский из того же коммита, если бандл собирается разом.

Для остальных восьми сказок (`bundled: false`) делать ничего не нужно — исправление доедет само,
когда клиент отреагирует на `contentVersion`.

## 4. Вопрос, который стоит закрыть

Судя по симптому, привязка слайдов завязана на наличие `{m:|f:}` в тексте страницы. По контракту
это не так: гендерные варианты иллюстраций клиент должен брать из массива `genderedPages`
в ответе `GET /api/tales/:id` (`API.md §5`, `UNITY_INTEGRATION.md`), а маркеры в тексте — это
только про текст.

Эти два набора **никогда не совпадали**. Для `golden_egg`:

- `genderedPages` (реальные файлы `page_N_boy` / `page_N_girl`): **35** страниц —
  `0..9, 11..15, 17..29, 33, 37, 38, 39, 40, 42, 45`;
- маркеры в тексте: **22** страницы.

Так что даже сейчас, после нашего отката, привязка по маркерам даёт не тот набор картинок,
что реально существует. Подтвердите, пожалуйста:

- [ ] биндер слайдов читает `genderedPages` из API или парсит `{m:|f:}` из текста?
- [ ] если парсит — планируете переключить на `genderedPages`? Тогда наш откат станет
      страховкой, а не единственным, что держит фичу.
- [ ] у bundled-сказки `genderedPages` берётся из ответа API или из локального манифеста?

## 5. Отдельно: `contentVersion` и bundled-сказки

Два момента, где серверный контракт сейчас неудобен — скажите, если мешает, поправим:

1. `contentVersion` в `GET /api/tales` — это максимум по всем языкам. Правка только казахского
   поднимает версию и для русских, и для узбекских пользователей: у `golden_egg` сейчас
   kz=4, ru=1, uz=2, а в списке отдаётся 4. Можем добавить `contentVersions: {ru, kz, uz}`
   и `contentVersion` в `GET /api/tales/:id`, чтобы вы могли обновлять только протухший язык.
2. Для `bundled: true` сервер намеренно не отдаёт `downloadSize` — качать нечего. Если ваша
   сверка версий по бампу `contentVersion` сбрасывает локальную копию сказки, то у bundled-сказки
   после сброса не остаётся ничего: докачать неоткуда. Проверьте, что для `bundled` сверка
   версий либо пропускается, либо не трогает данные из `StreamingAssets`.

## 6. Как проверить после сборки

- Казахская `golden_egg`, все 49 страниц: слайды привязаны и показываются.
- Гендерные иллюстрации переключаются: у девочки на стр. 0 текст «Бұл **қыз** әжесімен бірге
  ауылда тұрады», картинка — girl-вариант.
- Русская и узбекская `golden_egg` не сломались.
- Любая скачиваемая сказка на казахском (например `space_race`) после обновления библиотеки
  показывает новый текст и привязанные слайды.
