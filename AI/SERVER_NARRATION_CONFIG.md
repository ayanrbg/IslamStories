# Серверу: два поля в конфиге, чтобы чинить озвучку без релиза клиента

Клиент уже читает их. Пока сервер их не отдаёт — ничего не меняется.

## Куда

В тот же ответ, что уже отдаёт конфиг лог-зеркала (`GET /api/logs/config`,
а также тело ответа `POST /api/logs`). Клиент разбирает его вторым парсером и
игнорирует отсутствующие поля.

```jsonc
{
  "hasConfig": true,
  "enabled": true,
  "level": "warn",

  "narrationEpoch": 1,              // ← новое
  "defaultNarratorGender": "female" // ← новое
}
```

## Что делают поля

| Поле | Тип | Действие на клиенте |
|------|-----|---------------------|
| `narrationEpoch` | int | Клиент хранит последнее увиденное число. Как только пришло **большее** — удаляет всю кэшированную дикторскую озвучку по всем сказкам и озвучивает заново. Начните с `1`. |
| `defaultNarratorGender` | `"male"` \| `"female"` | Голос диктора для тех, кто ни разу не выбирал его в приложении. Явный выбор пользователя всегда сильнее и не перетирается. |

## Когда поднимать `narrationEpoch`

Когда починили что-то на своей стороне, а у людей на устройствах лежит плохое
аудио: сломанный TTS-голос, неверная персонализация, обрезанные файлы. Подняли
на единицу — все клиенты сами перегенерировали. Релиз в сторах не нужен.

Не поднимайте «на всякий случай»: это оплаченный заново TTS для всех активных
пользователей.

Если когда-нибудь появится предзаписанная озвучка (`hasDefaultNarration: true`),
уберите папку `narration` из списка на удаление в `AssetCache.ClearGeneratedNarration`:
клиент скачивает её только при загрузке сказки и сам не восстановит.

## Проверка

В логах клиента появится строка `narration_epoch_reset epoch=<N>` — по одной на
устройство, ровно один раз на каждое повышение.
